# اختيار Runway وإعداد التطوير

## الاختيار الحالي

| السطح | متى نستخدمه؟ | قرار ماسك الآن |
|---|---|---|
| Models | توليد مباشر بمعايير محددة | الاختيار الحالي: Gen-4.5، نص إلى فيديو، 5 ثوانٍ، عمودي |
| Model Routers | اختيار النموذج آليًا عبر سياسة أو مجموعة نماذج | نؤجله حتى نحتاج أكثر من نموذج |
| Characters | شخصية/أفاتار في تفاعل مباشر | خارج هدف أول فيديو من وصف |
| Recipes | استعمال وصفة جاهزة لحالة استخدام | نراجعه عندما تتحدد حالة مثل إعلان منتج |
| Workflows | ربط خطوات متعددة | مرحلة لاحقة بعد نجاح مسار التوليد الواحد |

أبقينا PHP/XAMPP والواجهة العربية. أضفنا Node.js 22+ لأن مسار البدء الرسمي يطلب Node أو Python SDK. المكتبة المثبتة `@runwayml/sdk` بإصدار `4.21.0` مثبت في package-lock. لا توجد عملية توليد حقيقية في الاختبارات.

## الفرق بين MCP وSDK

MCP يتيح لأدوات Codex الوصول المصرح به لحالة حساب المطور وأدواته. يحتاج OAuth. SDK هو العميل الذي يستعمله التطبيق لتوليد الفيديو؛ يحتاج مفتاح API للمؤسسة. إكمال OAuth لا يضع مفتاح SDK تلقائيًا داخل التطبيق.

تمت إضافة تعريف الخادم `runway-dev-mcp` سابقًا، لكن محاولة الدخول انتهت بمهلة OAuth دون تأكيد نجاح. لم تتوفر أدوات Runway الحسابية في هذه الجلسة، ولم يتم التحقق من المشاريع أو الرصيد. لا نفترض أن تعريف الخادم يجعل أدواته متاحة فورًا داخل جلسة Codex الحالية.

عند إعادة الاتصال في بيئة Codex المستهدفة:

```bash
codex mcp add runway-dev-mcp --url https://dev.runwayml.com/mcp
codex mcp login runway-dev-mcp --scopes openid,profile,email,mcp:read,mcp:write
```

أكمل رابط OAuth الذي يعرضه الأمر، وانتظر رسالة نجاحه. إذا كان الخادم مضافًا بالفعل يكفي أمر login. بعد الاتصال نستخدم القراءة اللازمة مثل الهوية والمشاريع والنماذج والرصيد، قبل اختيار مشروع أو تجربة مدفوعة. لا ننشئ أو نغير موارد الحساب دون طلب بذلك.

## تشغيل التطبيق

1. ثبّت Node.js 22+ وPHP 8.2+ مع curl وmbstring.
2. داخل مجلد المشروع: `npm ci` ثم `npm start`؛ اترك النافذة مفتوحة.
3. اضبط `RUNWAYML_API_SECRET` في بيئة PHP التي يبدأ منها الخادم، أو المفتاح في config.local.php محليًا. لا تضع المفتاح في محادثة أو Git أو JavaScript.
4. شغّل XAMPP وافتح `http://localhost/video-ai/public/`، أو شغّل `php -S 127.0.0.1:8080 -t public` في نافذة ثانية.
5. زر الإنشاء يظل معطلًا حتى يتوفر المفتاح وتعمل خدمة SDK.
6. تجربة التوليد تستهلك رصيدًا. لم ننفذها خلال تطوير 0.2. افتح [تسعير Runway](https://docs.dev.runwayml.com/guides/pricing/) وتحقق من رصيد حسابك قبلها.

الخدمة لا تفحص الحساب عند /health ولا تبدأ توليدًا عند تشغيلها. يمر المفتاح من PHP إلى Node عبر loopback فقط، ولا يدخل سجل المهمة. عند تشغيل Apache يجب أن يرث متغير البيئة إن استعملته؛ ضبطه في طرفية أخرى وحدها لا يكفي.

### تخصيص المنفذ والتخزين

القيم الافتراضية: المنفذ 8787 ومجلد storage داخل المشروع. إذا غيرتها في config.local.php يجب أن تطابق متغيرات خدمة Node:

```powershell
$env:MASK_VIDEO_SDK_PORT = '8787'
$env:MASK_VIDEO_STORAGE_DIR = 'C:\xampp\htdocs\video-ai\storage'
npm start
```

تحقق من `php_cli` في إعداد PHP إذا كانت أداة التنزيل لا تعمل؛ الافتراضي يستعمل PHP_BINDIR. لا تعطّل التحقق من TLS لحل أخطاء الشهادات؛ اضبط CA في PHP وNode.

## استئناف آمن

يحفظ العامل رقم المزود ثم يستخدم `waitForTaskOutput()` بمهلة عشر دقائق. لا نكتب حلقة استطلاع مزود مخصصة. `maxRetries: 0` يمنع إعادة POST المدفوع تلقائيًا. ملف `.sdk.lock` لكل تجربة يمنع محاولة إرسالها من جديد بعد إعادة تشغيل الخدمة؛ لا تحذفه للتجربة نفسها.

عند إعادة تشغيل الخدمة أو فشل حفظ MP4، يرسل زر «متابعة نفس الطلب» معرّف المهمة المحلية فقط إلى PHP. ثم يستدعي العامل `tasks.retrieve(providerId).waitForTaskOutput()`، فيسترجع المهمة نفسها ورابطًا محدثًا إن بقيت النتيجة متاحة. لا يبدأ توليدًا جديدًا.

إذا فقد رقم المزود بعد إرسال غير مؤكد، راجع لوحة Runway ثم استخدم tools/recover.php كما في README. لا تستخدم هذه الأداة أثناء عمل العامل.

## المهارات المثبتة

اتباعًا لمسار البدء، ثُبتت وقرئت `runway-dev` و`runway-dev-models` داخل `.agents/skills`، مع روابط `.claude/skills` وملف skills-lock. لم ننفذ أي إنشاء حساب أو مشاريع أو موارد مدفوعة.
