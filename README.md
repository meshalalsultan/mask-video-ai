# ماسك — استوديو الفيديو بالذكاء الاصطناعي

**الفكرة:** تكتب وصف الفيديو بلغتك الطبيعية، فينشئ التطبيق مقطعًا حقيقيًا، يعرضه داخل الصفحة ويحفظ نسخة MP4 تستطيع تنزيلها.

**صاحب المشروع:** مشعل — Mask Trader.

**الإصدار:** نموذج أولي 0.1.

**آخر تحديث:** 4 أكتوبر 2026، بتوقيت الكويت.

**المستودع:** [meshalalsultan/mask-video-ai](https://github.com/meshalalsultan/mask-video-ai)، مع وصف وتوثيق عربيين. تمت معاينته بوضع Public بعد الرفع؛ تحويله إلى Private خطوة منفصلة من إعدادات GitHub إذا أراد صاحب المشروع الخصوصية.

> **أين وصلنا؟** تمت برمجة التطبيق الأولي والتحقق منه محليًا. لم يُنتج أول فيديو حقيقي بعد، لأن مفتاح Runway ورصيد حساب المطور لم يُضبطا. تم إنشاء مستودع GitHub ورفع الملفات إليه، ونجحت فحوص GitHub Actions للتغيير `a48ff45`. الاختبارات المحلية وبياناتها الاصطناعية ليست دليلًا على نجاح توليد لدى Runway.

## 1. لماذا نبني هذا المشروع؟

نريد لاحقًا منصة صناعة فيديو بالمحادثة. المستخدم يصف إعلانًا، يرفق صورًا، ثم يطلب تغييرات بلغة طبيعية، مثل: «عدّل المشهد الثاني فقط»، أو «كبّر الشعار بالنهاية». يحتفظ المشروع بصوره ومشاهده ومحادثته ونسخه، ويختار النظام أداة التنفيذ المناسبة.

القيمة المستهدفة هي إدارة صناعة الفيديو وتعديلاته، وتوفير إعادة توليد غير ضرورية. تعديل السعر أو حجم الشعار يمكن معالجته محليًا، بينما تغيير المشهد أو حركة الكاميرا يحتاج توليدًا جديدًا. هذه الإمكانات **خطة لاحقة وليست موجودة في الإصدار الحالي**.

أول هدف عملي الآن هو مشاهدة أول مقطع أنت كتبت وصفه. لذلك نبدأ بـ PHP يعمل على XAMPP؛ لا نحتاج Laravel أو MySQL أو FFmpeg أو نظام اشتراكات لتجربة هذا المسار.

## 3. طريقة عمل النسخة الأولى

1. تكتب وصفًا وتضغط «إنشاء أول مقطع».
2. المتصفح يرسل الوصف ومعرّف تجربة محليًا إلى `generate.php`.
3. السيرفر يتحقق من النص والجلسة ويثبت سجل التجربة قبل الطلب المدفوع.
4. السيرفر يرسل `POST /v1/text_to_video` إلى Runway ويحفظ رقم المهمة.
5. المتصفح يستدعي `status.php` كل 5 ثوانٍ، والسيرفر يسأل `GET /v1/tasks/{id}`.
6. عند نجاح المهمة، ينزّل السيرفر MP4 إلى `storage/videos`.
7. تظهر المعاينة والتنزيل عبر `media.php`، دون كشف رابط المزود المؤقت.

### لماذا نحفظ الفيديو؟

روابط نتائج Runway مؤقتة. توضح وثائقه أنها تنتهي خلال 24–48 ساعة، لذلك لا نعتمد عليها كمكتبة فيديو دائمة ولا نعرضها مباشرة للمستخدم. الملف المحفوظ محليًا يبقى إلى أن يحذفه صاحب المشروع، ويتطلب نسخه احتياطيًا يدويًا حاليًا.

### الإرسال ليس التوليد

الحصول على رقم مهمة يعني قبول طلب بدء العمل، وليس نجاح المقطع. معيار النجاح هو اكتمال التوليد، وحفظ MP4، وتشغيله وتنزيله.

## 5. تشغيل التطبيق على XAMPP في Windows

### المتطلبات

- PHP 8.2 أو أحدث. تحقق من نسخة XAMPP؛ الإصدار الأقدم يحتاج ترقية.
- إضافتا `curl` و`mbstring` مفعّلتان في `php.ini`، ثم إعادة تشغيل Apache عند تعديلهما.
- اتصال إنترنت يستطيع الوصول إلى Runway وخادم ملف الفيديو.
- حساب **Runway Developer** بمفتاح API ورصيد؛ لا تفترض أن اشتراك واجهة Runway العادية يوفر رصيد API.
- السماح لـ PHP بالكتابة داخل `storage/tasks` و`storage/videos`.

### الخطوات

1. نزّل ملفات المشروع من المستودع عبر Code → Download ZIP، أو استنسخه.
2. ضع المجلد هنا:

   ```text
   C:\xampp\htdocs\video-ai\
   ```

3. انسخ `config.example.php` في المجلد نفسه وغيّر اسم النسخة إلى `config.local.php`.
4. افتح `config.local.php` وضع مفتاح Runway بين علامتي الاقتباس:

   ```php
   'api_key' => 'ضع_مفتاحك_هنا',
   ```

   **ضع المفتاح على جهازك فقط؛ لا ترفعه إلى GitHub ولا تلصقه في المحادثة.** يمكن بدل ذلك ضبط متغير بيئة السيرفر `RUNWAY_API_KEY`، الذي له الأولوية على الملف المحلي.

5. شغّل Apache من لوحة XAMPP. لا تحتاج MySQL لهذه المرحلة.
6. افتح هذا الرابط على الجهاز نفسه:

   ```text
   http://localhost/video-ai/public/
   ```

7. اضغط وصف المثال أو اكتب فكرتك، ثم «إنشاء أول مقطع».
8. انتظر حتى يكتمل التوليد وحفظ الملف. إذا انقطعت المتابعة، اضغط «متابعة نفس الطلب».
9. شغّل الفيديو ثم نزّله. سجّل النتيجة في `docs/RESULTS.md`.

> مجلد الويب المقصود هو `public`. في XAMPP استخدم الرابط أعلاه، واحتفظ بملفات `.htaccess` لمنع الوصول المباشر للمجلدات الداخلية. في أي إعداد خادم لاحق اجعل جذر الموقع `public` حصريًا. جميع نقاط PHP ترفض الاتصالات غير المحلية حاليًا؛ هذه ليست نسخة متعددة المستخدمين.

### تشغيل بديل من الطرفية

داخل مجلد المشروع:

```bash
php -S 127.0.0.1:8080 -t public
```

ثم افتح `http://127.0.0.1:8080/` على الجهاز نفسه. لا تربط الخادم بـ `0.0.0.0` ولا تفتح منفذًا للإنترنت لهذا النموذج.

### تغيير المدة أو اتجاه الفيديو

في `config.local.php` فقط:

```php
'duration' => 10,       // يدعم التطبيق 5 أو 10 ثوانٍ
'ratio' => '1280:720',  // أفقي؛ الافتراضي 720:1280 عمودي
```

ابقِ `model` على `gen4.5` في 0.1. تغيير النموذج يحتاج مراجعة معاييره وليس استبدال اسمه فقط. كل تجربة جديدة قد تستهلك رصيدًا، والتكلفة تتبع حسابك وإعداداته.

## 6. أول وصف ومعيار نجاحه

استخدم وصفًا واحدًا كي يسهل الحكم على النتيجة:

> سيارة رياضية سوداء فاخرة في شارع حديث ليلًا، إضاءة نيون زرقاء تنعكس على هيكل السيارة. تبدأ الكاميرا بلقطة أمامية منخفضة ثم تتحرك ببطء إلى الجانب بينما تبدأ السيارة بالحركة. تصوير سينمائي وحركة ناعمة، دون نصوص على الشاشة.

نعتبر التجربة الأولى ناجحة إذا:

- سُجّل رقم مهمة Runway.
- وصلت الحالة إلى نجاح لدى المزود.
- حُفظ ملف MP4 داخل التطبيق.
- اشتغلت المعاينة والتنزيل.
- توافق المشهد إجمالًا مع الوصف، وسُجلت الملاحظات والتكلفة الفعلية.

لا نحتاج إعلانًا من 15 ثانية أو صورًا أو تعديلًا في هذه التجربة. هذه شروط مراحل لاحقة. إرسال الوصف بالعربية متاح برمجيًا، لكن جودة فهمه يجب الحكم عليها بعد التجربة الفعلية.

## 7. الحالات والأخطاء وكيف تتصرف

| الرسالة أو الحالة | معناها | الإجراء |
|---|---|---|
| خطوة الإعداد المتبقية | لا يوجد مفتاح | أنشئ ملف الإعداد المحلي وأضف المفتاح ثم حدّث الصفحة |
| `PENDING` / `THROTTLED` | المهمة تنتظر عند المزود | تابع نفس الطلب |
| `RUNNING` | المقطع قيد التوليد | اترك الصفحة تتابع |
| `SAVING` | التوليد نجح والتطبيق يحفظ الناتج | انتظر؛ إذا فشل الحفظ أعد المتابعة |
| `READY` | الملف المحلي جاهز | شاهد ونزّل وسجّل النتيجة |
| `FAILED` / `CANCELED` | لم تصل التجربة إلى ملف جاهز | راجع لوحة Runway؛ ثم يمكنك بدء تجربة جديدة |
| `SUBMISSION_UNKNOWN` | انقطع الإرسال أو لم يصل رد يؤكد رقم المهمة | لا تعاود التوليد فورًا؛ راجع لوحة Runway أولًا |
| رفض المفتاح أو الصلاحيات | مفتاح غير صالح أو مشروع غير مسموح | صحح إعدادات حساب المطور |
| رصيد غير كافٍ | رفض الطلب بسبب الرصيد | راجع رصيد API |
| خطأ شهادة SSL | شهادة الثقة في PHP غير مضبوطة | اضبط `curl.cainfo` و`openssl.cafile` لشهادة CA موثوقة؛ لا تعطّل التحقق من SSL |
| لا يمكن حفظ MP4 | صلاحيات/شبكة/ملف أكبر من حد 100MB/رابط غير مناسب | أصلح السبب ثم تابع نفس المهمة؛ لا يولد التطبيق مقطعًا بديلًا تلقائيًا |
| الصفحة تعرض 500 | خطأ PHP أو إعدادات | افحص سجل Apache/PHP وإصدار PHP والإضافات وصلاحيات التخزين |

### استعادة إرسال غير مؤكد

إذا عرض التطبيق رقم الطلب المحلي وحالة غير مؤكدة، افحص لوحة Runway. **تحقق من تطابق الوصف والوقت والمشروع قبل اختيار مهمة.**

إذا وجدت المهمة وعرّفها المزود، شغّل داخل مجلد التطبيق:

```bash
php tools/recover.php LOCAL_REQUEST_ID RUNWAY_TASK_ID
```

إذا تأكدت من لوحة المزود أن الطلب لم يُرسل أصلًا:

```bash
php tools/recover.php LOCAL_REQUEST_ID --not-submitted
```

في Windows يمكنك استخدام `C:\xampp\php\php.exe` بدل `php`. حدّث صفحة التطبيق في **جلسة المتصفح نفسها** بعد الأمر. الأداة لا تبدأ توليدًا ولا تتحقق من لوحة المزود بالنيابة عنك؛ قرار الربط اليدوي يحتاج الفحص أعلاه. لا تشغّلها بينما إرسال الطلب لا يزال جاريًا.

## 8. حدود النسخة الحالية

- لا يوجد تسجيل دخول أو إدارة وصول للإنترنت؛ التطبيق مقيد بالاتصال المحلي.
- ملكية الملفات مرتبطة بجلسة PHP. فقدان كوكيز الجلسة أو حذف بياناتها يفقد الوصول عبر الواجهة، رغم بقاء MP4 على القرص. احتفظ بتنزيلاتك.
- نعرض آخر طلب في الجلسة؛ توجد سجلات التجارب محليًا، لكن لا توجد صفحة مكتبة أو مشاريع بعد.
- يسمح بعملية نشطة واحدة في الجلسة وبحد 30 تجربة في الجلسة، وليس نظام حدود مدفوع شاملًا.
- منع التكرار يخص معرّف الطلب والجلسة؛ ليس ضمان exactly-once بين جهازك والمزود في كل حالة تعطل. لهذا توجد حالة الإرسال غير المؤكد.
- متابعة حالة المهمة ليست عاملًا يعمل بالخلفية. عند إغلاق الصفحة يتوقف الاستطلاع المحلي؛ قد يستمر Runway بالتوليد. أعد فتح التطبيق في الجلسة نفسها قبل انتهاء رابط النتيجة.
- لا توجد ترجمة أو تحسين تلقائي للوصف ولا إخراج صوتي مطلوب في 0.1.
- قد لا تتبع النتيجة كل كلمة من الوصف. لا يمكن ضمان جودة المقطع قبل التجربة.
- لا يوجد حساب آلي للتكلفة الحقيقية. الحقل `api_cost_actual` فارغ عمدًا؛ سجل المبلغ من حساب المزود يدويًا.
